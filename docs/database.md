# Database Documentation: The Deposit War Room

This guide explains each database table and field used in **The Deposit War Room** in simple, beginner-friendly terms.

The schema is built for **Supabase (PostgreSQL)**, but the application also includes an automatic client-side store so it can run immediately without database setup errors.

---

## 1. Entity Relationship Overview

```
 ┌─────────────┐
 │   parties   │
 └──────┬──────┘
        │ 1:N
 ┌──────▼──────┐       1:N       ┌──────────────────┐
 │  disputes   ├────────────────►│ deduction_claims │
 └──────┬──────┘                 └────────┬─────────┘
        │                                 │ 1:N
        │ 1:N                             ▼
        ├────────────────►       ┌──────────────────┐
        │                        │ evidence_items   │
        │ 1:N                    └──────────────────┘
        ├────────────────►       ┌──────────────────┐
        │                        │   evaluations    │
        │ 1:N                    └──────────────────┘
        ├────────────────►       ┌──────────────────┐
        │                        │negotiation_rounds│
        │ 1:N                    └──────────────────┘
        ├────────────────►       ┌──────────────────┐
        │                        │     consents     │
        │ 1:1                    └──────────────────┘
        ▼
 ┌─────────────┐
 │ settlements │
 └─────────────┘
```

## 2. Table-by-Table Breakdown

### 2.1 `disputes`
The main case file. Every dispute has a unique reference number (e.g., `DISP-2026-8821`).

| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | `TEXT PRIMARY KEY` | Unique ID of the dispute |
| `property_address` | `TEXT` | Full address (e.g. Flat 402, Palm Meadows, Whitefield, Bengaluru) |
| `city` | `TEXT` | City (default: Bengaluru) |
| `monthly_rent` | `NUMERIC` | Monthly agreed rent in ₹ |
| `security_deposit` | `NUMERIC` | Total security deposit paid by tenant in ₹ |
| `deposit_returned` | `NUMERIC` | Amount returned so far by landlord |
| `withheld_amount` | `NUMERIC` | Amount withheld by landlord (Deposit - Returned) |
| `tenancy_start_date`| `DATE` | Move-in date |
| `tenancy_end_date` | `DATE` | Lease end date |
| `move_out_date` | `DATE` | Actual physical handover date |
| `status` | `TEXT` | `DRAFT`, `SUBMITTED`, `EVIDENCE_COLLECTION`, `EVALUATION`, `NEGOTIATION`, `SETTLEMENT_ELIGIBLE`, `SETTLED`, `MEDIATOR_REVIEW`, `CLOSED` |
| `current_round` | `INTEGER` | Active negotiation round (0 to 3) |
| `created_at` | `TIMESTAMP` | Record creation timestamp |

---

### 2.2 `parties`
Information about the tenant and landlord involved in the dispute.

| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | `TEXT PRIMARY KEY` | Party ID |
| `dispute_id` | `TEXT REFERENCES disputes(id)` | Associated dispute |
| `role` | `TEXT` | `TENANT` or `LANDLORD` |
| `name` | `TEXT` | Full name of the person |
| `email` | `TEXT` | Email address |
| `phone` | `TEXT` | Phone number |

---

### 2.3 `deduction_claims`
Each specific item the landlord wants to deduct from the security deposit.

| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | `TEXT PRIMARY KEY` | Claim ID |
| `dispute_id` | `TEXT REFERENCES disputes(id)` | Associated dispute |
| `category` | `TEXT` | `PAINTING`, `FIXTURES`, `UTILITIES`, `UNPAID_RENT`, `CLEANING`, `OTHER` |
| `description` | `TEXT` | Explanation from landlord |
| `claimed_amount` | `NUMERIC` | Amount claimed by landlord (in ₹) |
| `invoice_amount` | `NUMERIC` | Actual invoice/bill amount, if available |
| `item_age_years` | `NUMERIC` | Age of damaged fixture in years (used for depreciation) |
| `invoice_date` | `DATE` | Date on the repair/painting bill |
| `tenant_response` | `TEXT` | Tenant's counter-statement or rebuttal |

---

### 2.4 `evidence_items`
Supporting documents, photos, and bills uploaded for each claim.

| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | `TEXT PRIMARY KEY` | Evidence ID |
| `claim_id` | `TEXT REFERENCES deduction_claims(id)`| Specific claim this evidence supports |
| `dispute_id` | `TEXT REFERENCES disputes(id)` | Parent dispute |
| `evidence_type` | `TEXT` | `MOVE_IN_PHOTO`, `MOVE_OUT_PHOTO`, `INVOICE`, `UTILITY_BILL`, `RENT_AGREEMENT`, `BANK_STATEMENT` |
| `title` | `TEXT` | Brief title (e.g., "BESCOM Bill June 2026") |
| `url` | `TEXT` | Image/document link |
| `condition_tag` | `TEXT` | `GOOD`, `NORMAL_WEAR_AND_TEAR`, `EXCESSIVE_DAMAGE`, `UNSANITARY` |
| `submitted_by` | `TEXT` | `TENANT` or `LANDLORD` |

---

### 2.5 `evaluations`
The explainable calculations generated by the Rule Engine.

| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | `TEXT PRIMARY KEY` | Evaluation ID |
| `claim_id` | `TEXT REFERENCES deduction_claims(id)`| Claim evaluated |
| `dispute_id` | `TEXT REFERENCES disputes(id)` | Parent dispute |
| `category` | `TEXT` | Claim category |
| `claimed_amount` | `NUMERIC` | Original landlord demand |
| `allowed_amount` | `NUMERIC` | Lawfully permissible deduction |
| `rejected_amount` | `NUMERIC` | Disallowed amount |
| `rule_type` | `TEXT` | `STATUTORY_RULE`, `ODR_POLICY`, `DEMO_ASSUMPTION` |
| `statutory_citation`| `TEXT` | Specific legal section (e.g. "Section 108(m) TPA 1882") or empty if policy |
| `explanation` | `TEXT` | Human-readable explanation of why the deduction was adjusted |
| `evaluator_status`| `TEXT` | `ACCEPTED`, `PARTIALLY_ACCEPTED`, `REJECTED`, `MANUAL_OVERRIDE` |

---

### 2.6 `negotiation_rounds`
A permanent audit log of each counteroffer round between the parties.

| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | `TEXT PRIMARY KEY` | Round ID |
| `dispute_id` | `TEXT REFERENCES disputes(id)` | Parent dispute |
| `round_number` | `INTEGER` | 1, 2, or 3 (Strict limit!) |
| `landlord_offer` | `NUMERIC` | Total deduction landlord is willing to accept |
| `tenant_offer` | `NUMERIC` | Total deduction tenant is willing to concede |
| `gap_amount` | `NUMERIC` | Absolute difference: `abs(landlord - tenant)` |
| `gap_percentage` | `NUMERIC` | Gap as % of highest offer |
| `landlord_message`| `TEXT` | Optional note from landlord |
| `tenant_message` | `TEXT` | Optional note from tenant |
| `created_at` | `TIMESTAMP` | Timestamp when round occurred |

---

### 2.7 `consents`
Records prototype digital consent from both parties.

| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | `TEXT PRIMARY KEY` | Consent ID |
| `dispute_id` | `TEXT REFERENCES disputes(id)` | Parent dispute |
| `party_role` | `TEXT` | `TENANT` or `LANDLORD` |
| `party_name` | `TEXT` | Signer's name |
| `agreed_deduction`| `NUMERIC` | Agreed settlement amount |
| `consented_at` | `TIMESTAMP` | Live timestamp in IST |

---

### 2.8 `settlements`
The final resolved agreement.

| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | `TEXT PRIMARY KEY` | Settlement ID |
| `dispute_id` | `TEXT REFERENCES disputes(id)` | Parent dispute |
| `total_deposit` | `NUMERIC` | Original security deposit |
| `final_deduction` | `NUMERIC` | Mutually agreed deduction |
| `refund_amount` | `NUMERIC` | Net refund paid to tenant (`Deposit - Deduction`) |
| `settled_at` | `TIMESTAMP` | Settlement execution timestamp |
| `pdf_hash` | `TEXT` | Unique cryptographic hash for agreement integrity |
